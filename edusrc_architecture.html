仅收录教育/人社/中科院资产 平台收录范围规定 Scope Guard 自动过滤非 .edu.cn / 非授权目标 软约束（可配）
测试后清理痕迹 测试完成及时删除遗留文件 每个 Active Probe 有对应的 cleanup 回调 最佳实践
禁止上传 Webshell / 木马 文件上传测试规范 文件上传 POC 仅上传无害探针文件（.txt / harmless） 硬约束
禁止保存 / 传播获取的数据 数据保护义务 发现敏感数据仅记录"存在泄露"元信息，不存储实际数据 硬约束

📈 ROI 优先级体系（发现成本低 → 评分高）

P0 最高优先

弱口令 Weak Password

发现成本：⭐⭐ 极低
EDUSRC 评分：7-9（高危）
每目标仅 3-5 次尝试（admin/admin, admin/123456, admin/admin888）。 内置教育行业专用字典：身份证后6位、学号后6位、@123456。 命中率极高，统一认证 / VPN / 后台系统都是常见入口。
P0 最高优先

敏感信息泄露 Info Leak

发现成本：⭐ 近乎零
EDUSRC 评分：4-10（中危 ~ 严重）
被动探测 .git/config、.env、.DS_Store、/actuator/env 等敏感路径。 GitHub 搜索 password / db / accessKey 关键字。 全部 GET 请求，零风险，十分钟覆盖数千目标。
P1 高优先

未授权访问 Unauthorized

发现成本：⭐⭐ 极低
EDUSRC 评分：7-9（高危）
JS 解析提取隐藏 API 路径，直接 GET 测试。 修改登录返回包绕过前端校验。 Druid Monitor、Swagger UI、Spring Boot 端点都是重灾区。
P1 高优先

越权漏洞 IDOR

发现成本：⭐⭐ 极低
EDUSRC 评分：4-9（中危 ~ 高危）
核心操作：修改请求中 userid / studentId 参数，用另一账号验证。 水平越权（看别人数据）、垂直越权（普通用户执行管理操作）。 AI 辅助识别参数语义，自动生成越权测试用例。
P2 中优先

Nday 漏洞 & 通杀

发现成本：⭐⭐⭐ 中等
EDUSRC 评分：7-10（高危 ~ 严重）
指纹识别 → 匹配 Nday POC 库 → Nuclei 轻量验证。 发现一个 CMS 漏洞后，自动在 FOFA 搜索同版本目标扩散验证。 若依 / Druid / Spring Boot / GitLab 常见 Nday。
P2 中优先

逻辑缺陷 Logic Flaw

发现成本：⭐⭐⭐ 中等
EDUSRC 评分：7-9（高危）
任意密码重置、验证码爆破 / 绕过、支付金额篡改。 短信 / 邮箱轰炸（发现成本极低，但评分较低 0-4）。 AI 分析业务流程，识别异常逻辑路径。
P3 常规

文件上传 Getshell

发现成本：⭐⭐⭐ 中等
EDUSRC 评分：7-10（高危 ~ 严重）
后缀绕过、Content-Type 欺骗、截断上传。 仅上传无害探针文件证明解析，不上传 Webshell。 KindEditor / UEditor / eWebEditor 等编辑器上传漏洞。
P3 常规

SQL 注入

发现成本：⭐⭐⭐⭐ 较高
EDUSRC 评分：7-10（高危 ~ 严重）
报错注入轻度验证，不做深度利用。 仅证明注入存在（database 名称 / 版本），不拖取数据。 搜索框、登录框、参数过滤不严的接口。

📡 数据流设计

├─ INPUT seed_domains.txt 用户输入的目标域名列表
├─ L1 → assets.json {domain, ip, port, source, timestamp}
├─ L2 → targets.json {url, title, tech_stack, value_score, is_login, is_admin}
├─ L3 → passive_findings.json {url, vuln_type, evidence_path, confidence: 0.9}
├─ L4 → active_findings.json {url, vuln_type, poc_used, evidence, rank_estimate}
└─ L5 → report.md 去重聚合后的最终漏洞报告，含 edusrc 提交草稿

🔗 通杀联动机制

一洞多吃，自动扩散

当 L4 在目标 A 发现一个 Nday 漏洞后，触发通杀链路：

① 提取漏洞 CMS / 组件名称 + 版本号
② → FOFA / 鹰图搜索同版本资产
③ → 在 L2 已知资产中匹配同类指纹
④ → 自动对同类目标执行该 POC
⑤ → 聚合为"通杀漏洞"报告，一稿多投

🧠 AI 增强能力

LLM 辅助判断，覆盖自动化盲区

传统扫描器难以检测的逻辑类漏洞，交给 AI：

🤖 越权检测 — 分析 API 参数语义，识别 userid / orderId 等敏感参数，自动生成越权测试用例
🤖 逻辑漏洞 — 分析重置密码 / 支付 / 注册等业务流程，发现逻辑缺陷
🤖 POC 生成 — 根据漏洞描述和响应特征，自动生成 Nuclei 模板
🤖 报告润色 — 自动生成 edusrc 格式的漏洞描述与复现步骤

🚀 分阶段实施路线图

Phase 1 — 基础设施 + 被动检测
资产发现 + 存活检测 + 敏感路径探测

搭建项目骨架，实现 L1（子域名+FOFA）+ L2（httpx存活+指纹）+ L3（敏感路径GET探测）。
这是整个架构的基座，完成后即可批量产出中危 / 高危漏洞。

⚡ 预计产出：Spring Boot 端点泄露、.git 泄露、.env 泄露、Swagger/Druid 未授权

Phase 2 — 弱口令 + 未授权访问
高频漏洞，快速上分

实现 P0 弱口令检测（教育行业专用字典，3-5次/目标）和 P1 未授权访问检测（JS解析路径+返回包修改绕过）。
接入第一阶段产出的"有登录口"目标列表。

⚡ 预计产出：统一认证弱口令、管理系统弱口令、API 未授权访问

Phase 3 — Nday POC + 通杀扩散
一洞多吃，数量翻倍

建立指纹→POC映射库，集成 Nuclei 引擎。实现通杀联动：发现漏洞 → FOFA搜索同版本 → 自动扩散验证。
优先覆盖教育行业常见框架：若依、Spring Boot、ThinkPHP、Laravel、Druid、GitLab。

⚡ 预计产出：ThinkPHP RCE、若依弱口令、GitLab Nday、Spring Boot heapdump

Phase 4 — AI 越权 + 逻辑漏洞
覆盖传统自动化盲区

集成 LLM API，实现：API参数语义分析→越权测试用例生成；业务流程分析→逻辑缺陷识别。
越权类是 eduSRC 上占比最高的漏洞类型之一，AI 增强可大幅提升自动化覆盖率。

⚡ 预计产出：水平/垂直越权、任意密码重置、验证码绕过

Phase 5 — 报告自动化 + 运营优化
提升交付效率

实现去重聚合、Rank 评分预估、Markdown 报告生成、edusrc 提交草稿一键生成。
飞书 / 钉钉通知推送。持续优化字典库、指纹库、POC 模板库。

⚡ 预计产出：全自动报告链，从发现到提交草稿一键完成

💡 设计原则

核心思路：先铺面，再打点，最后通杀

🎯 铺面 — L3 被动检测覆盖所有资产，零成本批量产出
🎯 打点 — L4 按价值评分 + ROI 优先级，聚焦高价值目标
🎯 通杀 — 发现一个 CMS 漏洞，自动在所有同类目标扩散
三条铁律：
① 被动优先于主动（先 L3 后 L4）
② 低侵入优先于高侵入（先弱口令后 SQL 注入）
③ 通杀优先于单点（先扩散后深挖）
